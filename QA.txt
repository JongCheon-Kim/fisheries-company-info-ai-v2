[v2.3 안정화 QA - TODO]
1. FIS 자동 재시도
   - 최초 실시간 조회가 HTTP 400 또는 일시 오류로 실패하면 1~2초 후 자동 1회 재시도
   - 재시도 성공 시 정상 실시간 결과 표시
   - 무한 재시도 금지

2. 성공 응답 캐시
   - FIS 조회에 성공한 기업의 재무정보를 일정 기간 캐시에 저장
   - 같은 기업 재조회 시 FIS가 일시 실패하더라도 최근 성공 캐시 사용 가능
   - 캐시 데이터의 기업코드(cpnyCd), 조회시각, 연도범위 관리

3. 정적 데이터 fallback
   - 실시간 조회 및 자동 재시도 모두 실패할 경우 현재 보유한 2024 정적 핵심재무를 fallback으로 표시
   - 정적 Master에 값이 없는 항목은 '-' 표시
   - 실시간 값과 정적 fallback 값을 혼합하여 하나의 값처럼 표시하지 않음

4. 조회상태 표시
   - 화면에 데이터 출처/상태를 명확히 표시
   - 예: [실시간], [캐시], [백업], [조회실패]
   - 사용자가 현재 표시값의 출처를 즉시 알 수 있어야 함

5. 오류 메시지
   - FIS 일시 오류 시 앱 전체 오류처럼 보이지 않도록 처리
   - 기업 기본정보/지도는 계속 사용 가능해야 함
   - 재시도 중/실패/백업 전환 상태를 간단히 안내

6. 모바일 PWA 업데이트/캐시 QA
   - GitHub Pages 최신 버전 배포 후 모바일에서 구버전 화면이 잔존하는지 확인
   - Chrome/카카오톡 링크/설치형 PWA 각각 최신 버전 진입 확인
   - Service Worker 캐시 버전 갱신 전략 검토
   - 향후 필요 시 index.html 등 핵심 진입파일 network-first 적용 검토

7. 검색 부문 선택 QA
   - 전체/생산/가공/유통/외식 부문칩 클릭 후 검색 드롭다운 유지
   - 부문 선택 즉시 목록 필터링
